# Source climate category palette

The native core now implements BiomeType's original curve/linear lookup,
per-category normalization and identity-based temperature/humidity pair selection.
Two fresh JVMs using the exact dev23 production JAR agree on 68,929 records.
Native debug/release match all 137,864 fields: the complete 256x256 normalized
input grid, boundary/out-of-range inputs, all 11 category ranges, every sampled
identity pair and normalization values. Invalid indexes return an explicit error;
the palette never supplies a substitute for an out-of-range index.

The 65,536-byte runtime table is a portable representation of TerraForged's own
finite climate palette, produced by its genuine BiomeTypeLoader from the original
biomes.png. The capture verifies the actual JAR's PNG bytes against the repository
source image and verifies normalized biomes.txt content too. Source algorithm,
resource, JAR and table hashes are frozen together. No Minecraft assets or sampled
world/terrain data are included. The installer checks those source identities and
the complete data layout before copying/checking the runtime table. The core
algorithm independently derives category ranges from that table; expected
observations are never generated by the native code.

These are 11 internal climate categories, not registered Minecraft biomes. This
does not complete native registration/selection of the 17 classic biome variants,
continent/climate cell generation, filtered tiles, chunks or native client/save
acceptance. Palette colors used only by the preview renderer and arbitrary
external palette modifications are outside this numerical scope.

Run `install_biome_table.py` and `verify_native_noise.py --family biome` with a new
report path. Windows/Linux CI checks both the source-owned data and the numerical
observations. Original TerraForged/ReTerraForged MIT attribution is retained.
