# Additional native noise sources

White, Cubic, PerlinRidge, SimplexRidge and Billow now match two independent
captures from the genuine packaged dev23 Java classes. The source-family corpus
contains 126,653 records and 128,458 fields per native profile. Six signed seeds,
17 by 17 coordinates, three interpolation choices and zero/one/multiple octave
cases include negative integer boundaries and world-border-scale inputs.
High-octave cases use bounded coordinates and cover the inherited PerlinRidge /
Billow split: normalization uses all requested spectral weights, while sampling
clamps its active octave count to 30. SimplexRidge instead uses Simplex2's bound
and a fixed 30-entry weight array. Cubic preserves its pre-normalization reported
bounds and its initial sample even at zero octaves.

The separate 376-record float-power corpus observes the genuine Math.pow float
overload, signed zeros, subnormals, large positive inputs, negative inputs with
integral powers, fractional powers and five 32-step spectral-weight sequences.
All raw bits match in debug and release locally. This finite domain is not a
proof of cross-platform libm equivalence for every float or NaN input; both CI
platforms rerun it. Registered Power/PowerCurve graph nodes are still unfinished.

Run `verify_native_noise.py --family sources` and `--family power` with distinct
new report paths. Frozen Java observations are never generated by native code.
Both capture tools refuse replacement, verify class package origins, and require
two fresh JVMs to agree. The numerical sources are not yet activated in Horizon,
and do not implement the complete cell/river/filtered-tile pipeline.
