# Issues and blockers reviewed on 2026-11-07

The Horizon port remains experimental and is not yet qualified for modpacks.
This review checks current GitHub state and retained local evidence. It does
not represent a fresh run of the entire Java or native acceptance matrix.

## Issues and current recovery state

1. **Host CI and protected integration recovered.** The API reported enabled
   workflows but rejected dispatch with HTTP 422, "Actions has been disabled
   for this repository." The signed-in Actions page exposed a separate disabled
   fork-workflow gate. Re-enabling it restored actual jobs. Manual runs alone
   were not accepted by protected merging (four required checks were expected),
   so the final stack received fresh PR-triggered checks. All four required
   contexts passed: [verify and launcher](https://github.com/TheApple05/horizon/actions/runs/42421324133),
   [updater-tests and protocol-and-shaders](https://github.com/TheApple05/horizon/actions/runs/42421323970).
   [Host PR 11](https://github.com/TheApple05/horizon/pull/11) merged into main
   at `638568adb8472b467cd05a11e576938fe55f52d2`. PR 8 was included automatically;
   superseded stacked PRs 9 and 10 were closed with links to that merge. Strict
   required contexts and admin enforcement remained enabled. Specialized-runner
   parity jobs were not counted as passing.

   The completed native functional baseline also passes the latest
   [Windows/Linux foundations](https://github.com/TheApple05/TerraForged-Horizon/actions/runs/42427541863)
   and [all five integration modes](https://github.com/TheApple05/TerraForged-Horizon/actions/runs/42427541766).
   [Native PR 3](https://github.com/TheApple05/TerraForged-Horizon/pull/3) merged
   at `d3de4fe981633e408da70e14a824b3321f626946` with its client/save evidence.

2. **The complete default renderer suite now passes serially.** The old
   parallel Windows process was terminated after more than 20 minutes; its
   truncated log did not identify a stuck case. The fresh verbose run completes
   in 162.74 seconds: 1,387 pass, zero fail and 43 remain ignored, covering every
   one of the 1,430 listed cases without filtering. `RUST_TEST_THREADS=1` uses
   the existing test runner. Vulkan is the default backend; explicit GPU cases
   also exercise DirectX 12 on the RTX 3090. The LOD test initially observed
   without output completes normally.

   [The combined renderer/Python record](../validation/horizon-host-renderer-python-v1.json)
   retains commands, executable/log hashes, counts and ignored case names.
   The original parallel timeout's cause remains unestablished; serial completion
   does not qualify parallel GPU-test execution, ignored resource cases or full
   vanilla parity. No production renderer change or test suppression was needed.

3. **All-17 client/save acceptance passes, including first-target frozen marsh.**
   The old v5 teleport-to-last-query interval was only 6.382 seconds; its zero
   counters described client storage/streaming and did not establish a server
   stall. The fresh final-v3 run makes frozen marsh its first teleport and
   reaches visible terrain in 30.2 seconds, with authoritative server generation
   progressing.

   The [completed raw report](../validation/horizon-native-classic-ui-final-v3.json)
   uses the exact native.dev4 package on staged host `b33109ad`. Both clients
   exit cleanly. All 17 natural classic views render; real saved FULL biome
   vectors match native generation in 18 chunks after the first save and 19
   after reopening and generating distant terrain, totaling 56,832 stored
   quart values. The native stem, seed and generation flags also match. Checked
   original and copied resource hashes remain unchanged. Initial natural
   survival spawn is healthy and grounded. Later captures use recorded noon
   controls in the scratch QA world.

   High-camera fog made the original stone-forest geometry view inconclusive
   and limited Bryce's view. A separate [lower-camera run](../validation/horizon-native-lower-pillars-v1.json)
   resolves those limits using an ordinary copy of the completed saved world.
   Its source world, checked resources and pinned artifacts remain unchanged.
   The [independent agent image review](../validation/horizon-native-classic-ui-image-review-v1.json)
   inspects all 23 PNGs and verifies their hashes. It records visual smoke
   acceptance, not Java scenery parity or user aesthetic approval. Unmodified
   pillar previews are included in the classic-runtime integration document.

   Native performance remains open: Bryce takes 236.5 seconds and cold steppe
   300.3 seconds in the first client's teleport sequence. Those are uncontrolled
   UI waits, not a throughput/FPS benchmark. Subsequent profiling identifies
   redundant carver-selection biome queries. A separate [performance candidate](native-carver-performance.md)
   preserves all six full terrain snapshots in alternating runs and reduces the
   measured batch median from 5.98 to 1.85 seconds. Its fresh client/save and CI
   checks are still in progress; broad performance acceptance remains open.

5. **The local shell validation baseline is resolved.** The older suite ran
   663 tests with 14 skips and one missing-WSL-Bash failure. Windows resolved

   passes: 663 tests, 13 skips, zero failures, in 157.718 seconds. No machine-wide
   PATH or WSL setting changed. The old failed log remains preserved.

6. **QA resource preparation improved; one unexplained verifier exit remains
   documented.** Serial copying was stopped before game launch after 345.6

   check [passes](../validation/horizon-native-resource-copy-v1.json).

   A second session-managed verifier disappeared during preparation without a
   final report or captured exception; its cause is unestablished. Partial JSON

   files (747,255,411 bytes) in 31.3 seconds and passed checked resource hashes.
   Its separate process/log/exit receipt records the completed successful run.
   No game files were downloaded, linked, or committed.

## Remaining acceptance work

Native source-carver configuration still inherits the engine's vanilla settings
rather than the Java port's complete preset configuration. Independent Java
whole-feature block parity, mixed structures/decoration, standard launcher
installation, controlled native performance and native mod combinations remain
unfinished. These are explicit implementation or acceptance gaps, rather than
checks silently counted as passing. Complete original TerraForged fidelity has
not been established.

## Reporting requirement and review

Repeated failures, unexpectedly long stalls and missing required evidence must
be surfaced promptly, with their impact, attempted fixes and next debugging
step. They must not wait until another feature milestone to be reported.

This report was checked against current GitHub workflow state, completed log
endings, report JSON statuses, screenshot counts and process state. A separate
draft review was cross-checked against the underlying evidence. The report distinguishes stopped/interrupted tests,
unverified fixes, environment failures, remaining work and completed checks.
