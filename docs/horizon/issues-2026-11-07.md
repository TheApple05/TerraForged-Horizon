# Issues and blockers reviewed on 2026-11-07

The Horizon port remains experimental and is not yet qualified for modpacks.
This review checks current GitHub state and retained local evidence. It does
not represent a fresh run of the entire Java or native acceptance matrix.

## Issues and current recovery state

1. **Host CI and protected integration recovered.** The API reported enabled
   workflows but rejected dispatch with HTTP 422, "Actions has been disabled
   for this repository." The signed-in Actions page exposed a separate disabled
   fork-workflow gate. Re-enabling it restored actual jobs. Manual runs alone
   were not accepted by protected merging (four required checks were expected),
   so the final stack received fresh PR-triggered checks. All four required
   contexts passed: [verify and launcher](https://github.com/TheApple05/horizon/actions/runs/42421324133),
   [updater-tests and protocol-and-shaders](https://github.com/TheApple05/horizon/actions/runs/42421323970).
   [Host PR 11](https://github.com/TheApple05/horizon/pull/11) merged into main
   at `638568adb8472b467cd05a11e576938fe55f52d2`. PR 8 was included automatically;
   superseded stacked PRs 9 and 10 were closed with links to that merge. Strict
   required contexts and admin enforcement remained enabled. Specialized-runner
   parity jobs were not counted as passing.

2. **The broad Windows renderer suite remains unqualified.** The old isolated
   process was terminated after exceeding 20 minutes. The retained `pr_ready`
   failure output contains only its final 40 lines, so it cannot identify one
   stuck test. Separate checks passed six renderer biome tests and 581 core/world
   tests, with seven core/world tests ignored. The next full renderer run will
   retain verbose test output and use serial Vulkan tests, after the active
   client run, to avoid competing GPU/CPU load. Neither a complete renderer nor
   vanilla parity pass is claimed yet.

3. **Frozen marsh reproduced successfully; all-17/save testing is ongoing.**
   The old v5 teleport-to-last-query interval was only 6.382 seconds; eight
   status samples spanned 4.900 seconds with advancing frames and ticks. Its
   zero counters, including misleading `server.chunks`, described client-side
   storage/streaming and did not establish an integrated-server stall.

   The fresh final-v3 test uses the exact final-v1 staged client and matching
   HMOD, with seven isolated homes. Frozen marsh was its first teleport and
   became visible in 30.2 seconds. Authoritative `memory` samples showed actual
   server generation progressing. Two image reviewers found coherent local
   snow, ice, waterways and trees, with no obvious texture/geometry defect.
   Bryce subsequently passed in 236.5 seconds; cold marshland also passed. As
   of 22:46 UTC, three of 17 classic views are complete and cold steppe is
   loading. No complete all-17 or save/reopen pass is established. Initial
   natural survival spawn was healthy and grounded; later QA screenshots use
   separately recorded noon/daylight controls for visibility. These loading
   observations are not controlled performance benchmarks.

4. **The native staged-gameplay lint failure is fixed and remotely checked.**
   Five pre-existing nested conditions became Clippy errors when AST staging
   removed ordinary comments. The host fix preserves their order and comments
   using let chains; no lint suppression was introduced. Native pin
   `b33109ad199d2e149c80c8dc7d97f879c4f4ffec` was published in commit `0d991bc`.
   [All five native integration modes](https://github.com/TheApple05/TerraForged-Horizon/actions/runs/42420437194)
   now pass, including UI checks of both gameplay and client libraries. The
   [foundation checks](https://github.com/TheApple05/TerraForged-Horizon/actions/runs/42420437190)
   also pass on Windows and Linux. The full staged client built locally in
   10 minutes 46 seconds.

5. **The local Bash baseline cause is identified; the focused checks pass.**
   The older Python suite ran 663 tests with 14 skips and one missing-WSL-Bash
   failure. Windows resolved `bash` to its unconfigured System32 WSL stub while
   `sh` resolved to Git Bash. Prepending the installed Git Bash `bin` directory
   only for the validation child process makes all seven `test_server_panels`
   tests pass. No machine-wide PATH or WSL setting changed. A fresh complete
   local Python suite is still pending; its older failure is retained.

6. **QA resource preparation improved; one unexplained verifier exit remains
   documented.** Serial copying was stopped before game launch after 345.6
   seconds with about 6,000 of 28,180 files copied. The initial ten-minute
   estimate was corrected from timestamps. Eight bounded ordinary-copy workers
   now preserve independent files, metadata and empty directories, with at most
   16 in-flight files and atomic progress records. A 41-file integrity/error
   check [passes](../validation/horizon-native-resource-copy-v1.json).

   A second session-managed verifier disappeared during preparation without a
   final report or captured exception; its cause is unestablished. Partial JSON
   and files remain preserved. The supervised third attempt copied all 28,180
   files (747,255,411 bytes) in 31.3 seconds and passed checked resource hashes.
   Its separate process/log/exit receipt continues tracking the active client.
   No game files were downloaded, linked, or committed.

## Remaining acceptance work

Native source-carver configuration still inherits the engine's vanilla settings
rather than the Java port's complete preset configuration. Independent Java
whole-feature block parity, mixed structures/decoration, standard launcher
installation, controlled native performance and native mod combinations remain
unfinished. These are explicit implementation or acceptance gaps, rather than
checks silently counted as passing. Complete original TerraForged fidelity has
not been established.

this review, and arbitrary modpack compatibility or complete classic parity is
not claimed.

## Reporting requirement and review

Repeated failures, unexpectedly long stalls and missing required evidence must
be surfaced promptly, with their impact, attempted fixes and next debugging
step. They must not wait until another feature milestone to be reported.

This report was checked against current GitHub workflow state, completed log
endings, report JSON statuses, screenshot counts and process state. A separate
draft review was cross-checked against the underlying evidence. The report distinguishes stopped/interrupted tests,
unverified fixes, environment failures, remaining work and completed checks.
